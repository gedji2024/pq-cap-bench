def to_text(m: dict) -> dict:
    """(a) AgentDojo message -> the same message with plain-string content."""
    if isinstance(m.get("content"), list):
        return {**m, "content": get_text_content_as_str(m["content"])}
    return m


def to_blocks(m: dict) -> dict:
    """(b) message with plain-string content -> AgentDojo's block format, text unchanged."""
    if isinstance(m.get("content"), str):
        return {**m, "content": [text_content_block_from_string(m["content"])]}
    return m


class TextLLM:
    """The agent LLM as MELON sees it: string-content messages in, string-content reply out."""

    def __init__(self, llm):
        self.llm, self.name = llm, getattr(llm, "name", "llm")
        self.replies: dict = {}          # id(string-content reply) -> (AgentDojo reply, its text)

    def query(self, query, runtime, env=EmptyEnv(), messages=(), extra_args=None):
        q, rt, e, out, ea = self.llm.query(query, runtime, env, [to_blocks(m) for m in messages], extra_args)
        t = to_text(out[-1])
        self.replies[id(t)] = (out[-1], t.get("content"), t)   # t kept alive so its id is not reused
        return q, rt, e, [*messages, t], ea

Line-by-line reasons:
- `to_text` (a): MELON reads `m["content"]` as a string (masked-run file text `... + original_msg["content"]`, `transform(message["content"] or "")`); AgentDojo's block list is joined with `get_text_content_as_str`, which is how AgentDojo renders content to text (non-None blocks in order, newline-joined). `None` content is passed through.
- `to_blocks` (b): MELON builds string-content messages (system copy, the few-shot sample, `general_instructions`, the `random.txt` call and result, the stop message, the replaced tool output); each string is wrapped as one block with `text_content_block_from_string`, text unchanged.
- `TextLLM.query` (a)+(b): MELON calls `self.llm.query(...)` twice per detection step (original and masked run) with string messages; they go to the agent LLM as blocks (b) and the reply comes back as a string message (a), appended to MELON's own list so that MELON's in-place edits (`updated_messages[-2]["content"] = ...`, `updated_messages[-1] = llm_message`) act on its own objects, as with a string-content LLM. `self.replies` keeps the original reply so it can be returned unchanged.
- `AdaptedMELON.query`, `text = [to_text(m) ...]` (a): the messages handed to MELON's unmodified `query`.
- `orig`, `back`, `to_blocks(m)` (b): the messages MELON returns go back to the pipeline in block format; a message MELON did not change (same object, same text) is returned as the original AgentDojo object, a changed or new one (replaced tool output, stop message, new reply) is wrapped with `to_blocks`.
- `extra_args = {} if extra_args is None else extra_args`: no effect in the pipeline (AgentDojo always passes `extra_args`); it only avoids MELON's shared mutable default `{}` when the adapter is called directly in tests.
Not touched: the masked-prompt wording, `transform_tool_calls`, the tool-call bank, the embedding comparison, the `> 0.8` cutoff, `threshold=0.1`, the order of operations, the replacement and stop on detection. `detect` is wrapped only to capture its printed `cosine_sim:` lines (stdout redirected), then returns MELON's result unchanged. `is_injection` handling in `PromptInjectionDetector.query` (README step 1) is not needed: `MELON.query` overrides it, and its stop message has `tool_calls=None`, which ends AgentDojo's `ToolsExecutionLoop`.
Equivalence test (`tests/test_melon_adapter.py::test_equivalence`, 22 deterministic trajectories, stub LLM and stub embeddings, network patched to localhost): MELON unmodified with plain-string messages and the adapted class with block messages give identical detection decisions, returned messages (role, text, tool calls), tool-call banks, embedding inputs, tool-output replacement and stop message in 22/22 cases, including no tool call, benign calls, an injected call repeated in the masked run, near-duplicates at cosine 0.79 (no detection) and 0.81 (detection), and a bank carried over two steps.
